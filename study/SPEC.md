# Spire Smash — план 3D-плейабла (по референсу Stack Ball)

Задание для модели-исполнителя (Sonnet). Работа ведётся собственными скиллами (в репозиторий не входят).
Референс: 4 скриншота игры Stack Ball (чужой материал, в репозиторий не включён).

Решения, согласованные с пользователем:
- механика hold-to-smash + огненный шар;
- **свой бренд** «Spire Smash»: никаких логотипов и названий Stack Ball;
- полный цикл с эндкардом;
- **гладкие стилизованные кольца**, не воксели;
- все модели процедурные, внешних GLB нет.

## 1. Что не так с оригиналом и что делаем лучше

| Оригинал | У нас |
|---|---|
| Пустой плоский градиентный фон, глазу не за что зацепиться, скорость падения не ощущается | Трёхслойный фон: градиент неба по глубине, парящие low-poly острова и облака с параллаксом вверх, мягкие боке-круги. Туман в цвет низа неба |
| Плоский свет без теней, кольца «картонные» | Key-свет сверху-слева, тень от шара на кольцо под ним, скос (bevel) на сегментах, лёгкий rim |
| Чёрные сегменты просто тёмные | Глянцевый «обсидиан» с тонкой малиновой кромкой. Опасность читается сразу, и кромка пульсирует, когда шар летит на чёрное |
| Один цвет на уровень | Цвет колец плавно меняется по высоте (тёплый → холодный), посередине небо переходит из «заката» в «сумерки», так прогресс видно глазами |
| Разлом без последствий | Сегменты разлетаются с вращением + мелкие осколки, на кольце остаётся клякса-след, шар сплющивается при ударе, лёгкий shake |
| Огненный режим — просто оранжевый шлейф | Шар раскаляется (emissive), пламенный шлейф, тёплый тинт экрана, speed-lines, чёрное разлетается на куски лавы, бас-удары |
| Финиш — плоский круг | Подиум с шахматным верхом, конфетти, шар прыгает на нём, камера плавно отъезжает → 3D-эндкард |

## 2. Механика (всё в `live/sim.js`, детерминированно, 120 Гц, без `Math.random`, только хэш `h1`)

**Мир** в sim-px. Ось `y` идёт вниз (глубина), угол `a` задаёт поворот вокруг оси башни. `U = 0.01` м/px.
Маппинг в сцене меняется относительно шаблона: **y → −Y (вертикаль)**, а не Z. Опиши это в шапке `scene.js`.

**Башня:**
- `N` колец (`K.N = 60`), шаг `K.GAP = 60` px;
- кольцо `i` лежит на `y = i·GAP`;
- 12 сегментов по 30° каждый (зазор 1.5°);
- `R_OUT = 200`, `R_IN = 72`, столб `R_POLE = 66`.

Уровень задаётся данными: `RINGS[i] = { off, black: bitmask12 }`, где `off = i · K.TWIST` (спираль, `TWIST = 0.18` рад).
- Кольца 0–5 — без чёрного (обучение).
- Кольца 6–29 — один чёрный клин из 2–3 сегментов, ширина растёт.
- Кольца 30–43 — 1–2 сегмента. Это «разгонная» зона: тут гарантированно копится огонь.
- Кольца 44–55 — 6–8 чёрных из 12. Пройти можно только огнём: это wow-зона.
- Кольца 56–59 — по 3 чёрных.
- Дальше финиш-платформа `y = N·GAP + 40`.

**Вращение:** `rot(t) = K.ROT · t`, `ROT = 1.5` рад/с.

**Шар.** Стоит на фиксированном угле перед камерой (`BALL_A = 0`) на радиусе `(R_IN+R_OUT)/2`, `BALL_R = 30`.
Сегмент под шаром: `seg = floor(mod(BALL_A − rot − off, 2π) / (π/6))`.
- **Не держим палец:** шар прыгает на верхнем целом кольце. Каждый контакт даёт `vy = −K.BOUNCE (900)`, `g = K.G (2600)`. Отскок от чёрного безопасен.
- **Держим палец:** шар летит вниз с постоянной `K.SMASH_V = 480` px/s (≈8 колец/с). При контакте:
  - цветной сегмент → **всё кольцо разбивается** (`S.broken[i] = t`), `+1` к счёту, `heat += 1/K.FIRE_N` (`FIRE_N = 14`);
  - чёрный сегмент без огня → смерть.
- **Огонь:**
  - `heat ≥ 1` включает `fire` на `K.FIRE_T = 2.6` с;
  - в огне чёрное тоже бьётся, очки ×2;
  - отпущенный палец сжигает `heat` со скоростью `K.HEAT_DECAY = 0.6`/с;
  - `heat > 0.5` → состояние «раскалён» (только визуал).
- **Смерть:** реклама без жёсткого фейла.
  - `K.LIVES = 2`. После первой смерти — 0.9 с на осколки шара, затем респаун над этим же кольцом с баннером «RELEASE ON BLACK!».
  - После второй смерти — `end` с `endWhy = 'lose'`.
- **Финиш:** контакт с платформой → `S.winT`. Через `K.END_AFTER_WIN = 1.6` с `end` с `endWhy = 'win'`.
- **Первое чёрное в обучении.** Если игрок держит палец и шар окажется на чёрном через ≤ 2 кольца — один раз за игру включается slow-mo `K.SLOWMO = 0.35` на 0.8 с, ставится флаг `S.warnT` (для HUD: «LET GO!»).
- **Таймеры эндкарда** — из шаблона: `END_NO_INPUT 12`, `END_IDLE 10`, `END_MAX 28`.
- **Камера:** `S.cam = [0, camY]`, где `camY` только растёт и следует за шаром со сглаживанием (как в оригинале: на отскоке камера не поднимается). `S.zoom` фиксирован, в огне чуть меньше (отъезд на 6 %).
- **События в `S.ev`:** `bounce`, `smash {ring, black}`, `heat50`, `fire`, `fireEnd`, `die`, `respawn`, `warn`, `finish`, `end`.

**Контракт шаблона сохранить:** `create/step/at/spawn/respawn/demoCheck/scriptInput`, `S.end/endWhy`, `S.firstIn/lastIn`, `VIEW`, `K`, `module.exports`.
- `S.money` = очки: HUD шаблона на него завязан.
- `inp.press` = держим палец.

**Attract-демо (`scriptInput`):**
- держит палец, если шар долетит до следующих `LOOK = 3` колец (с учётом времени и вращения) только по цветным сегментам;
- иначе отпускает;
- в огне держит всегда;
- первые 1.2 с не жмёт: идёт показ руки.

**`demoCheck` (биты рекламы, L = 24 с).** Должно выполняться:
- первый smash ≤ 2.5 с;
- хотя бы одна осознанная пауза перед чёрным;
- `fire` наступил в 10–15 с;
- в огне разбито ≥ 4 чёрных сегмента;
- `finish` ≤ 20 с;
- `end` ≤ L−3;
- ни одной смерти в демо;
- пассивный зритель доходит до эндкарда (это уже проверяет verify).

Настраивай числа **headless в node** через `SIM.at(t)`, никогда не по скриншотам.

## 3. Сцена (`live/scene.js`), стиль и бюджет

**Стиль** (записать в `art/style_bible.txt`):
- **Небо:** верх `#FFB36B` → низ `#C2507A` («закат»). К 60 % глубины переходит в `#6C4BC7` → `#2A1E5C` («сумерки»).
- **Кольца:** градиент по индексу `#FFE14D → #FF8A3D → #FF4F7B → #8F6BFF`. Material — MeshStandard, roughness 0.55, flatShading off.
- **Чёрные сегменты:** `#221E2B`, roughness 0.2, metalness 0.3, кромка-полоска emissive `#FF2E7E` (0.4, при угрозе пульс до 1.2).
- **Шар:** `#2EC9FF`, roughness 0.2. В огне emissive `#FF6A1A`.
- **Столб:** `#F4F1EC` с едва заметными горизонтальными бороздками (vertex colour).
- **Свет:**
  - HemisphereLight (небо/тёплый низ) 0.55;
  - DirectionalLight 1.15 сверху-слева-спереди, тени 1024, бокс ±4 м вокруг шара;
  - туман цвета низа неба, near 6 m / far 22 m.
- **Камера:** pitch −28°, FOV 50. Башня занимает 62–72 % ширины экрана. Шар на 42–46 % высоты сверху, его диаметр 6–8 % высоты вида.

**Геометрия (всё процедурно, 0 байт ассетов):**
- **Сегмент** — `ExtrudeGeometry` кольцевого сектора 28.5°, толщина 0.22 м, bevel 0.03×2, curveSegments 6. Две `InstancedMesh`: цветные (`instanceColor`) и чёрные (+ отдельный тонкий instanced-меш кромки).
- **Окно рендера:** каждый кадр заполняй инстансы только для колец `[ringAtCam−4, ringAtCam+18]` (≈260 инстансов). Не держи 720 скрытых: скрытые инстансы тоже стоят вершин (см. Pitfalls).
- **Столб** — один цилиндр на видимый участок. **Финиш** — подиум (цилиндр + шахматная текстура из canvas) через `KIT.merge`.
- **Обломки** — `KIT.Pool` из той же геометрии сегмента: разлёт наружу + вверх, вращение, жизнь 0.9 с, гравитация. Плюс Pool мелких кубиков-чипов (8–12 на кольцо, цвет кольца). В огне чёрные куски «лавовые» (emissive).
- Всё **без состояния**: обломки вычисляются из недавних `S.ev` (`smash` с `t, ring, rot`). Сцена — чистая функция `(state, t)`.
- **Шар:**
  - squash 0.7/1.25 на 80 мс при `bounce`/`smash`, stretch 1.15 в падении;
  - шлейф — Pool из 10 затухающих дисков (в огне — пламя: оранжевые аддитивные спрайты с подъёмом);
  - тень-блоб под шаром дополнительно к shadow map;
  - клякса на кольце после отскока: плоский диск цвета шара, затухает 0.6 с.
- **Фон:**
  1. полноэкранный шейдерный градиент, цвета зависят от глубины;
  2. 6–8 процедурных парящих островков и облаков (`KIT.merge`, по 1 draw), на разных радиусах 8–16 м, медленно уплывают вверх при спуске камеры (параллакс 0.3–0.6);
  3. Pool из ~30 боке-кругов (аддитивные, мягкие) с параллаксом.
- **Огонь:** тёплый тинт (оверлей в HUD, альфа 0.12), speed-lines (Pool из вытянутых квадов), shake 4 px от `smash`.
- **Смерть:** шар разлетается на 12 осколков (Pool), чёрный сегмент вспыхивает.
- **Эндкард 3D:** затемнение мира, шар на подиуме медленно крутится и подпрыгивает, конфетти (Pool 80).
- `probe()` и `QA()` сохранить.
  - QA-состояния: `start`, `firstSmash`, `warn`, `heat50`, `fire`, `fireBlackSmash`, `death`, `finish`, `endcard_win`, `endcard_lose`.
  - В `probe` hero-бокс = шар. Цель 6–8 % высоты: в этой игре герой маленький, это нормально. Отрази это в PLAN.md.

**Бюджет** (по `probe.mjs`):
- draws ≤ 45;
- tris ≤ 150k вместе с тенями;
- 60 fps на 390×844;
- сборка ≈ 0.75 MB (без моделей) → влезает в лимит Meta 2 MB.

## 4. HUD (`live/hud.js`) и звук (`live/audio.js`)

Сохранить GENERIC-блоки шаблона: CTA-бар, эндкард + replay, рука + баннер, callouts, `HUD.hit`, `HUD.check`.
Удалить: джойстик, guide arrow, ценники и бейджи уровня машины.

- **Сверху:**
  - прогресс уровня: два круга «1» и «2», между ними полоса, заполнение = доля разбитых колец (цвет полосы = текущий цвет колец);
  - под ней счёт крупными белыми цифрами с тёмной обводкой.
- **Метр огня** — дуга вокруг шара (проекция `SCENE.proj`):
  - появляется при `heat > 0.15`;
  - цвет от белого к оранжевому;
  - в огне становится полным кольцом пламени и убывает по `FIRE_T`.
- **Попапы:**
  - «+1» над шаром (мелкие, затухают);
  - каждые 10 колец подряд — «PERFECT ×10»;
  - при `fire` крупно «ON FIRE!»;
  - при `finish` — «LEVEL COMPLETE!».
- **Обучение:**
  - рука внизу по центру с анимацией нажатия и баннер «HOLD TO SMASH» до первого нажатия;
  - при `warn` — «LET GO!» над шаром + пульс кромки чёрного;
  - после респауна — «RELEASE ON BLACK!»;
  - idle > 2.5 с → рука возвращается.
- **CTA-бар внизу всё время:** «PLAY FREE», мягко пульсирует.
- **Эндкард:**
  - логотип-текст «SPIRE SMASH» (canvas-текст с градиентом, без картинок);
  - заголовок по `endWhy`: `win` «LEVEL COMPLETE!», `lose` «SO CLOSE!», `time` «CAN YOU REACH THE BOTTOM?»;
  - статистика «54 rings smashed»;
  - большая кнопка CTA, replay мелко; весь экран = CTA.
- **Звук** (процедурный WebAudio, только после первого жеста):
  - `smash` — короткий «чпок», высота растёт с серией (полутон за кольцо, сброс при отпускании);
  - `bounce` — мягкий «бум»;
  - `warn` — тихий тик;
  - `fire` — нарастающий whoosh + бас на каждом ударе;
  - `die` — звон стекла;
  - `finish` — арпеджио-фанфара.

`tools/build.json`:
- `title "Spire Smash"`, store-ссылки — заглушки (пользователь даст реальные);
- `models: {}` — убрать `worker`;
- `images`: только `hand` (`coin` убрать, если HUD его больше не использует);
- удалить `live/models/worker.glb` из проекта.

## 5. Фазы и критерии готовности

Одна фаза — одна сессия. Состояние держи в `study/PLAN.md` (≤ 40 строк). Этот файл скопируй в проект как `study/SPEC.md`.

**Фаза 0 — проект (~5 мин)**
```bash
python3 new.py spire-smash --ref <скриншот>.webp --title "Spire Smash" --title "Spire Smash"
cd spire-smash && python3 -m http.server 8960 --bind 127.0.0.1   # в фоне; http://127.0.0.1:8960/live/index.html?ad=1&dev
bash verify.sh            # шаблон Timber Rush должен быть зелёным ДО изменений
```
Готово, когда: verify зелёный на нетронутом шаблоне, `study/SPEC.md` и `study/PLAN.md` записаны, `art/style_bible.txt` заполнен.

**Фаза 1 — sim.** Игровую часть `sim.js` переписываешь **один раз целиком**: шаблон — другая игра, это разрешено. Контракт оставь. Дальше только мелкие `Edit`.
Готово, когда `verify.sh` печатает `demo ok` и тайминги битов попадают в коридоры §2. Проверь headless-скриптом: время первого smash, `fire`, `finish`, `end`, число смертей в демо = 0. Ручная проверка тоже headless: шаг с `press` по чёрному без огня → `die`, с огнём → `smash`.

**Фаза 2 — сцена и вид.** Сначала graybox (кольца, шар, камера), потом стиль, фон, свет.
Готово, когда:
- `probe.mjs` укладывается в бюджет §3;
- шар 6–8 %, башня 62–72 % ширины;
- контакт-шит `probe.mjs --shots frames/probe` → `sheet.py ... --w 300`.

**Фаза 3 — HUD, звук, сочность.**
Готово, когда:
- `verify.sh all` зелёный (`qa.mjs` без перекрытий HUD, smoke без ошибок и внешних запросов, fps ≥ 50).

**Фаза 4 — варианты и выдача.** `variants/*.json` заменить тремя гипотезами:
- `fast_fire` — `{ "FIRE_N": 9, "FIRE_T": 3.2 }`: wow раньше (~9 с), проверяем, поднимает ли ранний power-fantasy CTR;
- `short_tower` — `{ "N": 42 }` (и пропорционально зоны): эндкард на ~15 с, проверяем вклад самого эндкарда;
- `risky` — `{ "ROT": 2.1, "LIVES": 1 }`: больше напряжения и смертей → «SO CLOSE!», проверяем, кликают ли проигравшие чаще.

Затем `python3 tools/build_playable.py --variant all`.
Выдача пользователю (по-русски, коротко): что попробовать, размеры по сетям из `dist/*/report.md`, fps, draws/tris, известные пробелы, следующий шаг.

## 6. Правила для исполнителя

- Экономия токенов обязательна: мелкие `Edit`, не перечитывать только что записанное, картинки смотреть только в контрольных точках (один даунскейл-шит), числа — через `verify.sh` и `probe.mjs`.
- `kit.js` и `tools/*` не форкать — только расширять, если не хватает примитива (например, шейдерный фон-градиент). Generic-добавки помечай комментарием.
- Сцена и анимации — чистая функция `(state, t)`. Никакого `Math.random` и накопительного состояния в `scene.js`: `render.mjs` и probe рендерят произвольный момент времени.
- Скриншоты WebGL снимать только через `__renderAt` / `__probe(name, true)`, иначе получится чёрный кадр.
- Никаких внешних запросов, никаких скачанных моделей. Если появится желание взять CC0-модель — сначала спросить пользователя.
- Не обещать в рекламе того, чего нет в игре.
- Неясно и влияет на результат → спросить пользователя. Иначе выбрать разумное и записать в PLAN.md.
